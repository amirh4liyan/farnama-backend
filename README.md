# فرنما — سرور (farnama-backend)

کد سمت سرور فرنما، سامانه معاونت فرهنگی دانشگاه. این مخزن API مورد استفاده اپلیکیشن اندروید و پنل مدیریت کارشناسان را فراهم می‌کند.

- **فناوری‌ها:** Python 3.13 ،Django 5.2 ،Django REST Framework و PostgreSQL 17
- **اجرا:** کل سرور با Docker Compose اجرا می‌شود
- **مخزن اصلی پروژه و مستندات:** [farnama-docs](https://github.com/amirh4liyan/farnama-docs)
- **اپلیکیشن اندروید:** [farnama-android](https://github.com/amirh4liyan/farnama-android)

## پیش‌نیازها

- **داکر:** Docker Engine به‌همراه افزونه Docker Compose
- **ابزار uv (اختیاری):** فقط برای افزودن وابستگی‌ها و شناخت کد توسط IDE لازم است؛ برای اجرای سرور لازم نیست

## راه‌اندازی اولیه (یک بار)

۱. مخزن را clone کنید و وارد پوشهٔ آن شوید:

```bash
git clone https://github.com/amirh4liyan/farnama-backend.git
cd farnama-backend
```

۲. فایل تنظیمات محلی (`env.`) را از روی نمونه (`env.example.`) بسازید:

```bash
cp .env.example .env
```

۳. در فایل `env.`، باید مقدار `DJANGO_SECRET_KEY` و `POSTGRES_PASSWORD` را عوض کنید. مقدار `POSTGRES_PASSWORD` را می‌توانید به صورت دلخواه تعیین کنید اما برای مقدار `DJANGO_SECRET_KEY` بهتر است با دستور زیر یک کلید مخفی امن بسازید:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

۴. شناسه کاربری خود را بررسی کنید:

```bash
id -u
id -g
```

اگر خروجی هر دو `1000` است، کاری لازم نیست. در غیر این صورت، به مسئول یکپارچه‌سازی (امیرحسین عالیان) اطلاع دهید.

۵. سرور را اجرا کنید:

```bash
docker compose up --build
```

در اولین اجرا، ایمیج‌ها دانلود و جدول‌های پایگاه داده ساخته می‌شوند. سرور روی `http://localhost:8000` در دسترس است.

۶. در یک ترمینال دیگر، با دستور زیر حساب مدیر بسازید:

```bash
docker compose exec web python manage.py createsuperuser
```

۷. با همین حساب در `http://localhost:8000/admin/` وارد شوید.

## کار روزانه

برای شروع کار، و همچنین بعد از هر `git pull`:

```bash
docker compose up --build
```

این دستور در صورت تغییر وابستگی‌ها ایمیج را به‌روز می‌کند، migrationهای جدید را اجرا می‌کند و سرور را بالا می‌آورد. سرور توسعه با هر تغییر در کد، خودکار دوباره بارگذاری می‌شود.

برای متوقف کردن:

```bash
docker compose down
```

داده‌های پایگاه داده با این دستور حفظ می‌شوند. افزودن گزینه `-v` به این دستور **همه داده‌ها را پاک می‌کند**.

## دستورهای پرکاربرد

| کار                               | دستور                                                         |
| --------------------------------- | ------------------------------------------------------------- |
| ساخت migration پس از تغییر مدل‌ها | `docker compose run --rm web python manage.py makemigrations` |
| ساخت اپ جدید                      | `docker compose run --rm web python manage.py startapp <نام>` |
| پوسته تعاملی Django               | `docker compose exec web python manage.py shell`              |
| مشاهده گزارش‌های سرور             | `docker compose logs -f web`                                  |

## افزودن وابستگی

وابستگی‌ها با uv و روی سیستم خودتان اضافه می‌شوند:

```bash
uv add <نام-بسته>
```

این دستور `pyproject.toml` و `uv.lock` را به‌روز می‌کند. هر دو فایل را commit کنید. سایر اعضا با اجرای بعدی `docker compose up --build` بسته جدید را دریافت می‌کنند.

## روند کار با Git

- **شاخه‌ها:** هر تغییر روی یک شاخه جداگانه انجام می‌شود و از طریق Pull Request وارد `main` می‌شود.
- **بازبینی:** هر Pull Request پیش از ادغام به تأیید نیاز دارد.
- **فایل‌های migration:** فایل‌های migration را همان کسی که مدل را تغییر داده می‌سازد و همراه همان تغییر commit می‌کند.
- **فایل `env.`:** هرگز commit نمی‌شود؛ تنظیمات نمونه در `env.example.` نگه‌داری می‌شود.

## ساختار پوشه‌ها

```
farnama-backend/
├── config/          تنظیمات کل پروژه و نقشه آدرس‌ها
├── accounts/        کاربران
├── associations/    تشکل‌ها و عضویت‌ها
├── Dockerfile       دستورالعمل ساخت ایمیج سرور
├── compose.yaml     تعریف سرویس‌های سرور و پایگاه داده
└── .env.example     نمونه متغیرهای محیطی
```

## نکته‌ها

- **شبکه ساخت ایمیج:** در `compose.yaml`، تنظیم `network: host` برای ساخت ایمیج عمدی است. روی شبکه‌هایی که از VPN یا تونل استفاده می‌کنند، دانلود بسته‌ها از شبکه مجازی Docker ناتمام می‌ماند و ساخت ایمیج شکست می‌خورد.
- **شناسه کاربری:** تنظیم `user` در `compose.yaml` باعث می‌شود فایل‌هایی که کانتینر می‌سازد (مانند migrationها) متعلق به کاربر سیستم باشند، نه root.
- **کلید مخفی:** اگر در کاراکترهای کلید مخفی علامت `'` وجود داشته باشد، باید مقدار آن را در `env.` بدون تک‌کوتیشن بنویسید.
